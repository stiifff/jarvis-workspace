# sections/terminals/ — terminal grid

Rendering of the terminals (xterm.js) + dashboard-like layout engine.

- **Files:**
  - `terminal.js` — terminal render/attach via WebSocket + xterm. The chrome of
    each card is generated by `workspace.js` (decorative CLI logo + maximize + ✕); no
    footer (the `t-footer` with CLI label + uptime was removed) and no `⋯` menu
    (its settings/shell-change options went with the shell subsystem; the AI is
    chosen when creating the terminal).
    Mouse selection ALWAYS local (drag/double/triple click; copy with Ctrl+C,
    NO copy-on-select) via 3 instance patches to xterm 5.3 — read the shared
    memory notes (`.jarvis/memory/`) on mouse selection before touching anything mouse/selection.
    QA handle: `window.terminalesXterm` (Map terminalId → {term, ws, ...}).
  - `terminal-layout.js` — **auto-tile** engine. **UMD module**: pure DOM-free
    logic (Node-testable) + DOM engine that self-installs in the browser.
    Mirrors the `window.JarvisEditor` pattern → exposes `window.TerminalLayout`.
    - Model: **fraction grid** `{ rows: [ { hFrac, cells: [ {id, wFrac} ] } ] }`
      that ALWAYS fills the container. On add/remove it re-tiles in a balanced
      grid (`cols=ceil(√N)`, last row stretches; max 9). Resize = panel divider
      (the neighbor shrinks/grows, doesn't move). Drag = swaps cells.
  - `quick-picker.js` — quick terminal picker (`.qp-overlay`). Exposes
    `window.QuickPicker` with `abrir()`, `cerrar()`, `init()`. Opens with Ctrl+\\
    (binding configurable as `jarvis.control.quick-terminal`). Shows 6 CLIs with their
    logos (`window.cliLogo`); creates the chosen terminal via `POST /api/terminals`.
  - `terminal-paste.js` — **pure UMD module**: paste decisions (Ctrl+V):
    text wins over image; image → upload to `/upload-image` and paste the path
    (never `\x16`: it forced the CLI to read Windows clipboard via WSL/powershell
    interop, 3.5s+ → endless "Pasting..."; `\x16` is only the fallback if the
    upload fails). See the shared memory notes (`.jarvis/memory/`) on Ctrl+V paste.
  - `terminal-flow.js` — **pure UMD module**: ack counter of the flow control
    PTY→WS→xterm (seventh layer of the tmux size-clamping note). The browser acks
    bytes ALREADY PARSED (`term.write` callback → `{'type':'ack','bytes':N}`)
    and the backend stops reading the PTY past 1MB unacked — so xterm's queue
    never reaches the 50MB where it DROPS data on hidden tabs (visual corruption
    until F5). terminal.js only declares `&fc=1` in the WS URL if this module loaded.
  - `__tests__/terminal-layout.test.js` — Node test (`require('../terminal-layout.js')`).
  - `__tests__/quick-picker.test.js` — Node test of the picker pure logic.
  - `__tests__/terminal-flow.test.js` — Node test of the ack counter.
- **Served at:** `/static/sections/terminals/`
- **Styles:** several terminal styles currently live in `shared/base.css`
  (interleaved with shared rules and `@media`); they weren't separated to avoid
  breaking the cascade.
